2. Design and Development Methodology

Our methodology has not changed since Assignment 1. We still work in a short, screen-first cycle:

  • Agree on the information architecture and visual system from A1 (teal workspace, sidebar navigation, card-based status).
  • Split the required screens among four people so each person owns a coherent slice of the product.
  • Implement the front end with mock data, then review navigation, validation, and visual consistency together.

We did not switch process because A2 is the implementation of the A1 design, not a new problem. The only adjustment was practical: later screens (History, Notifications, Queue Management) consume the same mock services as the earlier dashboards, so we added a shared localStorage layer instead of each person inventing a separate fake data set. That keeps the UI consistent for Assignments 3 and 4.

Work was divided by role and screen, not by “whoever is free”:

  • Person 1 — Authentication / UI foundation: login, registration, validation, navigation, shared CSS and components.
  • Person 2 — User interface: user dashboard, join queue, queue status, mock queue interactions.
  • Person 3 — Admin services: admin dashboard, service management, create/edit form, open/close queue.
  • Person 4 — Queue administration: queue management (reorder / remove / serve next), history, notifications, and closing remaining A2 form-spec gaps.

Everyone was responsible for regular GitHub commits, checking navigation between pages, keeping styling consistent, capturing screenshots of their screens, writing contribution notes, and reviewing this document.

3. Front-End Technologies and Responsibilities

QueueSmart is a single-page web app. We chose a small, conventional front-end stack so the A1 layout could be implemented quickly and reused in later assignments.

TechnologyWhy we used it
React 19 Component-based screens that map one-to-one to the A1 design. Client-side state is enough for mock queues, history, and notifications. No backend is required for A2.
Vite 6 Fast local development and a one-command production build (npm run dev / npm run build).
React Router 7 Real routes for login, registration, user pages, and admin pages. Role-aware navigation is part of the UX, not a single page of tabs.
lucide-react A consistent icon set that matches the teal / coral A1 palette without pulling in a full UI kit.
Plain CSS We kept the A1 look (DM Sans + Manrope, 7–8px radii, teal #137c75) by writing CSS directly instead of fighting a component library.
Browser localStorage Mock persistence for the session, services, active queue, history, and notifications. Acceptable for A2; replaceable with APIs in A3.

How to run the front end:

npm install then npm run dev, and open http://127.0.0.1:5173. Register or sign in with any valid email and a password of at least 8 characters. Choose User or Administrator before submitting — the two roles have different workspaces.

Figure 6. History. Past queues with date, service name, time in line, and outcome (Served, Left queue, Removed). Filter chips and summary stats are included.

Figure 7. Admin Dashboard. List of services, current queue lengths, and quick actions to open or close a queue. Recent activity notifications appear on the same page.

Figure 8. Service Management. Admins can create, edit, open/close, or delete services. Priority and expected duration are shown on each row.

Figure 8b. Create / Edit Service form. Service Name (required, max 100 characters), Description (required), Expected Duration in minutes (required), Priority (low / medium / high), category, location, and closing time.

Figure 8c. Service form validation. Required fields, length limits, numeric duration, and a time input for “Open until.”

Figure 9. Queue Management. View the queue for a selected service. Reorder visitors, remove a visitor (UI only, with confirmation), and serve the next user. Recently served visits are listed under the line.

Figure 10. Notifications (in-app). Queue updates and status changes appear in the top-bar notification center (unread badge, mark read / mark all read / clear). The user dashboard also shows a notifications summary.
